# Invoice Template Studio

Экран настройки шаблона счёта с живым предпросмотром. Тестовое задание для **Finanse plus** (SaaS для бухгалтерского учёта), с перспективой постоянного сотрудничества.

Код оценивают живые люди и читают как образец того, каким он будет в их репозитории. Работающая демка — необходимый минимум, а не цель.

## Стек: не обсуждается

Зафиксирован заказчиком и совпадает с их боевым проектом.

- TypeScript 5.7, `strict`
- React 19
- Next.js 16, App Router
- **Tailwind CSS 3** (не v4) + CSS Modules
- PostCSS + Autoprefixer
- pnpm 10

Состояние — Jotai 2.20.3 (**не 3.x**), `jotai-history` для undo/redo, `radix-ui` для примитивов, `react-colorful` для пикера, `lucide-react` для иконок. Обоснование каждого выбора — в `docs/ADR.md`.

Новые зависимости не добавлять без явного согласования. Особенно UI-библиотеки: задание требует собственного визуального решения, и MUI/Ant/Chakra/shadcn его обесценивают.

## Референс: что копируем, что нет

`docs/reference/customize-screen.jpg` — это **референс сценария, а не макет для пиксельного копирования**. Задание дословно требует «предложить собственную визуальную реализацию».

**Берём из референса:**

- состав настроек: название шаблона, логотип с тумблером показа, два цвета, разделы General / Content
- структуру документа: шапка с логотипом, метаданные, реквизиты сторон, таблица позиций, блок итогов, подвал с Terms и Statement
- сценарий: меняю настройку слева — сразу вижу результат справа
- действия Save / Cancel

**Не берём:** его вёрстку, палитру, типографику, компоновку панелей, стиль контролов. Всё это задаётся `docs/UI-SPEC.md`.

Если сомневаетесь, к какой категории относится деталь: состав и поведение — из референса, внешний вид — из UI-SPEC.

## Правила кода

**Граница Tailwind и CSS Modules.** Tailwind — композиция токенов: отступы, сетка, флекс, типографика, цвета, `hover`/`focus-visible`/`disabled`, адаптив, тёмная тема. Это ~85 % разметки.

CSS Module — когда строка классов переваливает за ~12 утилит или нужен селектор, которого нет в разметке: `::before`, `[data-state]` от Radix, потомок сторонней библиотеки, `@media print`, пользовательские CSS-переменные документа. Модуль лежит рядом с компонентом: `Toggle.tsx` + `Toggle.module.css`.

**Типы.** Никаких `any`, `@ts-ignore`, `as unknown as`. Если тип не сходится — проблема в модели, а не в проверке. Единственное допустимое исключение уже в коде и прокомментировано: сужение вычисляемого ключа в `fieldOf`.

**Деньги.** Только целые минорные единицы (гроши), округление один раз при выводе. Никаких `float` в расчётах. Это платформа бухучёта — арифметика должна сходиться.

**Форматирование.** Суммы, даты и проценты — через `Intl`, с явным `timeZone: 'UTC'`. Самописных форматтеров не писать.

**Состояние.** Компонент подписывается на конкретную линзу (`primaryColorAtom`), а не на весь `settingsAtom`. Подписка на корень убивает смысл выбранной архитектуры.

**Пересчёт итогов.** Скрытие блока Discount или Taxes убирает суммы из Total и Balance Due, а не просто прячет строку.

**Гидрация.** Черновик из `localStorage` читается только в эффекте. Любое чтение `window` во время рендера — ошибка.

**Комментарии** объясняют «почему», а не «что». Комментарий, пересказывающий код, удалить.

## Definition of Done

Задача не закрыта, пока все четыре команды не прошли чисто:

```bash
pnpm typecheck    # tsc --noEmit, ноль ошибок
pnpm lint         # ноль ошибок и предупреждений
pnpm test         # Vitest, ноль проваленных тестов
pnpm build        # успешная сборка
```

Для задач с версткой дополнительно: страница открыта в браузере и проверена на 1440 / 1024 / 768 / 390 px, в светлой и тёмной теме.

«Должно работать» и «я всё сделал» без вывода этих команд не принимаются.

## Чего не делать

- Не менять версии в `package.json` без согласования
- Не мигрировать на Tailwind 4 — в v4 `@apply` в CSS Modules падает без директивы `@reference`, а поддержка браузеров сужается
- Не добавлять `next/font/google` — шрифты только системные, чтобы сборка не зависела от внешней сети
- Не писать README «для галочки»: он часть сдачи
- Не трогать `docs/PLAN.md` — это согласованный документ. Расхождение с ним обсуждать, а не править молча
